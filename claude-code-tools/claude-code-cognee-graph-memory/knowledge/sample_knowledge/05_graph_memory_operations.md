# グラフ記憶の運用ノウハウ

## cognifyを呼ぶタイミング

cognifyは入力テキストに対してエンティティ抽出とグラフ構築を実行する。複数のrememberを実行した後、または長文ドキュメントを直接渡してcognifyすることで、新しいエンティティと関連性をグラフに反映する。cognifyを実行しないと、search(GRAPH_COMPLETION)やrecallは新しく追加したデータに対して推論できない。

## rememberとsave_interactionの使い分け

rememberは任意のテキストを永続記憶に保存する。ドキュメント・ルール・決定事項・障害記録に使う。save_interactionはQ-Aペアをセッションキャッシュに保存し、短い会話のやりとりに最適化されている。1往復の会話を記録する場合はsave_interactionを使い、永続グラフに即座に残したい内容はrememberを使う。

## search種別の選択

search(CHUNKS)はLLMコストなしで一致する原文を取得する。search(GRAPH_COMPLETION)は複数エンティティを横断する推論や関係性のサマリが必要な場合に使う。CHUNKSは決定論的で安価、GRAPH_COMPLETIONは設定したLLMを使うため、ローカルモデルが構造化出力で失敗するケースがある。

## recallのオートルーティング

recallは検索戦略を自動選択する。永続グラフにアクセスする前にセッションキャッシュ内のキーワード一致にフォールバックすることもある。予測可能な検索結果が欲しい場合はsearch(CHUNKS)を使い、recallはセッション認識のショートカットが許容できる場面に絞る。

## forget_memoryとgraph_only

forget_memoryはリレーショナル・グラフ・ベクトルの全ストアからデータを削除する。graph_only=Trueはグラフのエッジのみ削除し、元のチャンクと埋め込みは残すため、グラフ品質が劣化したが原文は検索可能なまま残したい場合に有効。コンテンツ自体が不要になった場合はデフォルト（完全削除）を使う。

## improveの使い方

improveはトリプレット埋め込みでグラフを拡張する。session_idsなしで呼ぶと埋め込み拡張ステージのみ実行する。カンマ区切りのセッションIDを渡すと、セッションキャッシュのQ-Aペアを永続グラフに橋渡しする処理も追加で走る。多くのセッションが蓄積された後、グラフを最近の活動と整合させるために定期的に呼ぶ。

## リセットとしてのprune

pruneはデータ層とシステムメタデータの両方を削除する。開発中にローカルCogneeの状態を完全リセットする唯一の方法である。prune実行後、最低1回のrememberとcognifyのサイクルが完了するまでsearchとrecallは失敗する。
