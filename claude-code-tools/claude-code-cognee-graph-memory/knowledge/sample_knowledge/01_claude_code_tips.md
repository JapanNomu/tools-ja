# Claude Code 活用ノウハウ

## セッション管理

Claude Codeはセッションが切れると会話の文脈が消える。重要な決定・ルール・障害記録はセッション中にrememberで登録しておくことで、次のセッションでrecallして引き出せる。

## コミット粒度

1タスク完了ごとに即座にgit commitする。複数タスクを1コミットにまとめると、どの変更がどのタスクに対応するか不明になり、ロールバック単位が曖昧になる。1タスク1コミットが原則。

## タスク管理

作業着手前にタスク管理表に追記し、進行中マークを付けてから着手する。タスク未登録のままファイルを変更するとhookにブロックされる。先にタスク登録、後で着手が鉄則。

## 指摘の受け方

ユーザーから指摘を受けたら、即座に記録してからタスク化する。記録より作業が先になると同じ指摘を繰り返し受けることになる。記録→タスク化→着手の順序を守る。

## git push

git pushはユーザーの明示的な指示がある場合のみ実行する。「コミットして」はpushを含まない。タスク完了・工程完了・プロジェクト完了はpushの理由にならない。

## 全件確認

テスト・レビュー・監査における確認作業は全件が原則。ファイル数が多くても対象を絞らない。代表ファイルだけ確認・主要なものだけ深掘りは品質保証の放棄にあたる。
