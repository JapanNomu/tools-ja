# CLAUDE.md 追記サンプル — Cognee グラフ記憶を自動的に使うためのルール

このファイルの内容を、あなたのプロジェクトの `CLAUDE.md` 末尾に追記してください。
Claude Code は CLAUDE.md を毎ターン読み込むため、ここに書かれたルールは AI に常に意識されます。

---

以下、`CLAUDE.md` に追記する内容（コピペ用）：

```markdown
## 🔴 知識の検索順序（絶対ルール）

作業着手前は、必ず以下の順序で関連知識を調べる。例外なし。

### 検索順序

1. **Cognee グラフ記憶を最初に検索する**
   `mcp__cognee__search(query, search_type="CHUNKS")` を呼び出し、過去のセッションで蓄積された
   ユーザー固有の経験・教訓・決定事項を引き出す。
2. **Cognee に該当がなければ `~/.claude/skills/` を読む**
   関連スキルの `reference.md` を Read する。
3. **それでも分からない場合のみユーザーに確認する**

### 適用対象（必ず検索する場面）

- ファイルの編集・作成・削除を伴う応答
- コマンド実行（Bash 等）を伴う応答
- 設計判断・方針決定・選択肢提示
- 障害対処・問題解決の方針提示

### 適用対象外（検索不要）

- 単純な Yes / No 回答
- ユーザーの質問の意図確認
- エコー応答（受け取った内容の繰り返し）

### Why（なぜこの順序か）

- Cognee はこのユーザー固有の最新の経験。skills は汎用・静的な共通ノウハウ。
  「具体的・新しい」記憶を優先することで、過去のミスの繰り返しを防ぐ。
- 「明らかに知っている」と思った内容ほど、過去に同じミスをしている可能性が高い。
  検索コストは数秒、ミスのリカバリコストは数時間〜数日。
- 検索のスキップ判断自体がミスの温床。例外なく検索する運用で物理的に防ぐ。

### 検索クエリの作り方

- ユーザーの指示・質問の主題語を1〜3個取り出して投げる
  - 例: 「Django のマイグレーションで気をつけることは？」
    → `search("Django migrate 注意", search_type="CHUNKS")`
- 作業対象のファイル名・関数名・エラー文字列もそのまま投げてよい
- ヒットしなければクエリを変えて2〜3回試す。それでもなければ skills へ進む

### 記録は hook が自動で行う

ユーザーの発言・AI の応答要点は `harness/hooks/` の hook が自動的に
`mcp__cognee__remember` で Cognee に登録する。AI が能動的に remember を呼ぶ必要はない
（呼んでもよい。重複登録は許容する）。
```

---

## このサンプルの位置づけ

- このファイル自体は配布物の一部であり、**そのままコピペして CLAUDE.md に追記する** ことを想定しています
- 内容を自分のプロジェクトの事情に合わせて削ってもかまいませんが、**「検索順序」と「適用対象」は削らないでください**（ハーネスの中核です）
- このサンプルとセットで `harness/rules/cognee_memory_usage.md` を `~/.claude/rules/` に配置することで、Why・実証経緯を含む詳細版が AI から参照されます

## 関連ファイル

- `harness/rules/cognee_memory_usage.md` — 詳細ルール（Why・実証経緯・共同納得の記録）
- `harness/hooks/auto_remember_user_message.py` — ユーザー発言を Cognee に自動登録
- `harness/hooks/auto_remember_completion.py` — 応答完了時の要点を Cognee に自動登録
- `harness/settings.example.json` — 上記 hook を有効化する設定例
- `docs/HARNESS_GUIDE.md` — 導入手順全体
